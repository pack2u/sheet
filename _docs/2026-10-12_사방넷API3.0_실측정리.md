## 0. ★ 가정이 거의 다 틀렸다 — 좋은 쪽으로

| 2026-10-09 가정 | **실제 (공식 문서)** |
|---|---|
| XML · 파일 URL 등록 방식일 수 있다 | **REST / JSON (UTF-8)** · OpenAPI 3.0 |
| 인증 = 샵ID + 인증키 | **OAuth2 Client Credentials → JWT(RS256)** |
| 테스트 환경 있는지 모름 | **샌드박스 있음** (`sandbox.sabangnet.co.kr`, 고정 응답) |
| 건별 성공/실패 오는지 모름 | **온다.** `206 부분성공` + `totalCount/successCount/failCount/results[]` |
| 클레임 조회 가능한지 모름 | **`GET /v3/sb/claim` 전용 API 있음** |
| 문의 API 있는지 모름 | **`GET /v3/sb/cs` · `POST /v3/sb/cs/answer`** 있음 |
| 몰 필터 되는지 모름 | **`shopCodeList` 로 필터.** `GET /v3/sb/mall/:shopDivCode` 로 몰 목록 조회 |
| IP 제한 모름 | **있음. 미등록 IP는 토큰 발급부터 거부** |

**한 줄로** — 내가 걱정한 것들은 대부분 이미 해결돼 있고, 못 본 함정이 따로 있었다(아래 3장).

## 1. 기본 규약

| 항목 | 값 |
|---|---|
| 프로덕션 | `https://api.sabangnet.co.kr` |
| 샌드박스 | `https://sandbox.sabangnet.co.kr` (고정 응답) |
| 경로 | 주문관리(OMS) `/v3/sb/**` · 창고관리(WMS) `/v3/sbf/**` |
| 형식 | HTTPS · UTF-8 · `application/json` |
| 인증 | OAuth2 Bearer JWT (RS256) |
| 공통 헤더 | `Authorization: Bearer {JWT}` · `X-Svc-Acnt-Id: {고객사 서비스계정 ID}` |
| 본문 상한 | **10MB** 초과 시 413 |
| 게이트웨이 타임아웃 | **기본 10초** (504) |
| TPS | **20 tokens/sec · 버스트 없음** (아래) |

### 요청량 제한 (TPS)

| 항목 | 값 |
|---|---|
| 기본 TPS | **20 tokens/sec** |
| 버스트 | **없음** — 유휴 시에도 20 이상 쌓이지 않는다. 순간 20건 초과 불가 |
| 집계 단위 | `SB_APP` = **고객사 단위** (같은 고객사의 모든 앱이 합산) |
| 초과 | `429 GW_RATE_001` |
| 응답 헤더 | `X-RateLimit-Limit` · `X-RateLimit-Remaining` · `X-RateLimit-Reset`(Unix ms) |
| 상향 | 운영 지원팀 문의. 다음 토큰 발급·갱신 시점부터 적용 |

20 TPS 는 우리에게 넉넉하다 — 송장도 상품도 **배열로 한 번에** 보내기 때문이다.
다만 「버스트 없음」이라 **동시 호출을 세마포어로 묶어야** 한다. 한꺼번에 21건을 던지면 그 자리에서 429다.

### 에러 포맷 (공통)
```json
{ "code": "GW_AUTH_001", "message": "인증 헤더(Authorization)가 누락되었습니다",
  "timestamp": 1712534400000, "status": 401, "path": "/v3/sb/orders" }
```

주요 코드 — `AUTH_008/009` 허용되지 않은 IP · 등록된 IP 없음 ·
`GW_AUTH_003` JWT 만료 · `GW_AUTH_010/011` IP · `GW_RATE_001` TPS 초과

> **403(IP·연동관계)은 재시도해도 자동 복구되지 않는다.** 재시도 로직에서 갈라야 한다.

## 2. 인증 — ★ 여기에 함정이 있다

```
POST /oauth2/token          Content-Type: application/x-www-form-urlencoded

grant_type  = client_credentials
clientType  = SB_APP  (자체개발)  |  SB_SOLUTION (제휴 파트너사)
clientCd    = Base62 20자리
timestamp   = Unix milliseconds   ※ 서버 시각 ±5분 30초 이내
secretSign  = Base64( BCrypt.hashpw("{clientCd}_{timestamp}", secret) )
authMode    = PRODUCTION | SANDBOX
```

JWT는 **3시간** 유효. 남은 시간이 30분 미만이면 같은 요청으로 자동 갱신된다.

### ★★ Apps Script 로는 토큰을 못 받는다 ★★

`secretSign` 이 **BCrypt** 다. Apps Script `Utilities` 에는 BCrypt 가 없다
(MD5·SHA·HMAC 뿐). GAS 안에서 BCrypt 를 직접 구현하는 것은 — 가능은 해도 —
돈이 걸린 자리에 손으로 짠 암호 코드를 두는 일이라 하지 않는다.

**→ 중계기(PHP)가 토큰을 받는다.** PHP 는 `password_hash($s, PASSWORD_BCRYPT)` 가 기본이다.
그리고 어차피 **IP 제한 때문에 중계기를 거쳐야 한다** (아래).

### IP 제한

> 허용되지 않은 IP는 **토큰 발급 및 API 호출이 모두 거부**됩니다.

GAS 는 발신 IP 가 구글 대역에서 유동 배정된다 — 등록할 수 없다.
로젠 때와 **똑같은 상황**이고, 해법도 같다.

```
[GAS] ──▶ siot.com 중계기 (222.122.39.14, 로젠에 이미 등록된 고정 IP)
             ├ 토큰 발급(BCrypt 서명) · 캐시(3시간)
             └ /v3/sb/** 호출 대행
```

`_logen_relay/relay.php` 가 이미 그 자리에서 돌고 있다. 같은 꼴로 `sabang.php` 를 올린다.

## 4. 1단계 — 운송장 `POST /v3/sb/waybill`

```json
{
  "forceUpdateYn": "N",
  "waybillList": [
    { "sbOrderNo": 2014010837,
      "deliveryCompanyCode": "001",
      "wayBillNo": 20250526172700,
      "hopeDeliveryDate": 20260114 }
  ]
}
```

**응답** — `200` 전체 성공 / **`206` 부분 성공** / 400 / 500
스키마: `totalCount` · `successCount` · `failCount` · **`results[]`**

> ★ 2026-10-09 설계의 수용시험 **S2(건별 성공/실패 식별)는 충족된다.**
>   1단계를 할 값어치가 있다는 뜻이다.

| 조건 | 내용 |
|---|---|
| 등록 가능 상태 | 주문확인 · 출고대기 · 교환발송준비 |
| 상태 변화 | **주문확인 상태에서 등록하면 → 출고대기로 바뀐다** |
| 수정 불가 | **쇼핑몰에 송장이 이미 전송된 경우** · 강제완료 |
| 강제수정 | `forceUpdateYn: "Y"` (수정 가능한 경우에 한함) |

우리 쪽 입력은 이미 있다 — `ss_사방넷엑셀저장` 이 만드는 행(주문번호·송장번호·택배사코드)이
그대로 `waybillList` 가 된다. 택배사코드도 `_PEP_CARRIER_SABANG_CODE_` 가 이미 001/002/007/037 을 쓴다.

### ★ 쇼핑몰 송신은 여전히 별도다 — 다만 «감시»는 된다

송신을 **거는** API 는 문서에 없다. 그러나 주문 조회 응답에 이 둘이 있다:

| 필드 | 뜻 |
|---|---|
| `WAYBILL_SEND_DT` | 운송장**송신**일시 |
| `WAYBILL_SEND_ERR_MSG` | 운송장**송신오류**메시지 |

그리고 `dateSearchCondition = 11` 이 **송장송신일** 기준 조회다.

→ **「사방넷에 넣었는데 쇼핑몰로 안 나갔다」를 무인으로 잡을 수 있다.**
   송신 자체는 사방넷 설정(자동화 서비스)이 하되, 빠진 건은 우리가 찾아 알린다.
   이것만으로도 지금보다 낫다 — 지금은 아무도 안 본다.

**상담 확인 사항은 그대로 남는다** — 자동화 서비스 금액·과금단위(정액/몰당/건당).

## 5. 주문 조회 `GET /v3/sb/order` — ★ 조회가 상태를 바꾼다

> API 요청 시 조건에 해당하는 **신규주문이 주문확인 상태로 변경**되며,
> 원치 않는 경우 `updateOrderStsYn` 을 **N** 으로 요청해야 합니다.

**폴링하려면 반드시 `updateOrderStsYn: "N"`.** 모르고 돌리면 신규주문이 전부
주문확인으로 바뀌어 쇼핑몰 쪽 흐름이 어긋난다. 이번 문서에서 가장 조심할 한 줄이다.

| 파라미터 | 쓸모 |
|---|---|
| `dateSearchCondition` | 1 배송희망일 · 2 주문일 · **3 취소접수일** · 4 취소완료일 · **5 반품접수일** · 6 반품완료일 · 7 출고완료일 · 8 교환접수일 · 9 교환완료일 · **10 송장등록일** · **11 송장송신일** · 12 입출고완료일 (미지정=수집일) |
| `shopCodeList` | **몰 필터** |
| `orderStatusList` | 18종 (아래) |
| `updateOrderStsYn` | **N 필수** (폴링 시) |
| `responseItems` | **REQUIRED** — 받을 필드를 골라 지정한다 |
| 조회기간 | 최대 6개월. 자사몰 필드(`ETC_*`) 포함 시 **2개월** |

**주문상태 18종**
`NEW_ORDER` 신규주문 · `ORDER_CONFIRM` 주문확인 · `DELIVERY_WAITING` 출고대기 ·
`DELIVERY_COMPLETED` 출고완료 · `DELIVERY_PENDING` 배송보류 ·
`CANCEL_RECEIPT` 취소접수 · `CANCEL_COMPLETED` 취소완료 ·
`EXCHANGE_RECEIPT` 교환접수 · `EXCHANGE_COMPLETED` 교환완료 ·
`RETURN_RECEIPT` 반품접수 · `RETURN_COMPLETED` 반품완료 ·
`EXCHANGE_SEND_READY` 교환발송준비 · `EXCHANGE_SEND_COMPLETED` 교환발송완료 ·
`EXCHANGE_RECALL_READY/COMPLETED` 교환회수준비/완료 ·
`RETURN_RECALL_READY/COMPLETED` 반품회수준비/완료 · `DISCARD` 폐기

응답 필드에 `ORDER_DT`(주문일시) · `ORDER_STATUS` · `PCSCP_CD`(택배사코드) ·
`ORG_SB_ORD_NO`(원본주문번호) · `WAYBILL_SEND_DT` 등이 있다.

## 6. 취소·클레임 — 「미출고 차단」이 성립한다

`POST /v3/sb/order-status` 는 **여러 건 일괄 + 건별 성공/실패**(206 + `results[]`)다.

**허용 상태전이**

| 현재 | 변경 가능 |
|---|---|
| 신규주문 | 주문확인 · **취소접수** |
| 주문확인 | **취소접수** |
| 출고대기 | **취소접수** |
| 배송보류 | **취소접수** |
| 교환발송준비 | **취소접수** |
| 출고완료 | 반품접수 · 교환접수 |
| 취소접수 | 취소완료 |
| 반품접수 | 반품완료 · 출고완료(클레임철회) |
| 교환접수 | 교환완료 · 출고완료(클레임철회) |

**추가 필수값** — 취소접수 `cancelReasonCode` · 반품/교환접수 `claimReasonCode` ·
반품/교환완료 `warehouseCode` + `receivedAvailableQty`+`receivedDefectiveQty >= 1`

→ 우리 쪽 차단 지점(세트분리 `보류(미발송)` · 대리공급 `발주대기`)과 맞물린다.
  `GET /v3/sb/claim` 또는 `dateSearchCondition=3(취소접수일)` 로 10~15분 주기 폴링하면
  세트분리 전·13:50 푸시 전에 닿는다.

## 7. 문의 — 답변까지 무인으로 간다

`GET /v3/sb/cs` 조회 · `POST /v3/sb/cs/answer` 답변 저장.

> **4. 쇼핑몰 송신: 사방넷에 저장된 답변은 최종적으로 원본 쇼핑몰로 송신되어 구매자에게 안내됩니다.**

상태값에 `ANSWER_SENT`(답변송신)가 있다.

→ **문의는 운송장과 달리 답변을 저장하면 사방넷이 쇼핑몰로 보낸다.**
  CS웹앱이 이미 가진 것들(`csManualPlaybooks` 처리 플레이북 · `csStockout` 입고예정일·대체상품 ·
  `csTrack/csLogen` 배송추적 · `csReturnFee` 반품비)과 붙이면 **초안 → 사람 승인 → 자동 송신**이 닫힌다.

## 8. 상품 — ★ 몰별 판매가·상세페이지가 «확정»됐다

### `POST /v3/sb/channels-product` — 채널별 상품 등록&수정

> 쇼핑몰별 상품정보(**판매가, 상품명, 상세설명, 재고비율**, 인증정보 등)를 등록 및 수정
> 여러 건의 상품을 일괄 처리 · 각 상품별 성공/실패 결과 반환

```json
{ "products": [{
    "shopCode": "shop0001",                          ← 몰
    "customProductCode": "PRD001",                   ← 우리 자체상품코드
    "salePrice": 15000,                              ← ★ 몰별 판매가
    "productName": "반팔티셔츠",                       ← 몰별 상품명
    "productDetailDescription": "면 100% 반팔티셔츠",   ← ★ 몰별 상세설명
    "shopMallStockRate": 50,                         ← 몰별 재고 «비율»(%)
    "shopMallShippingPolicyId": "B0000001",
    "productAttributeClassificationCode": "001",
    "productAuthorizationNumber": "CB1234567",
    "authorizationNumberIssueDate": 20260101,
    "authorizationExpiryDateFrom": 20260101,
    "authorizationExpiryDateTo": 20261231,
    "authorizationOrganizationName": "한국인증기관",
    "authorizationSphereName": "품질인증" }] }
```

→ **①몰별 판매가 · ③몰별 상세페이지가 사방넷 경로로 성립한다.** 몰 공식 API 를 따로 붙일 필요가 없다.
  `shopCode` 는 `GET /v3/sb/mall/:shopDivCode` 로 받는다. 우리 자체상품코드로 짝을 맞춘다.

### `POST /v3/sb/product/upsert` — ★ 부분수정이 된다

> 자체상품코드가 존재하면 **수정(U)**, 없으면 **등록(I)**
> **1회당 최대 5,000건**
> [수정 시 필드 처리] 필드 **누락/`null` 은 컬럼 미수정**, `""` 은 **컬럼 클리어**,
> 공백만 입력은 trim 되어 `""` 과 동일(상세설명·관리자메모 제외).
> 필수 필드를 `""` 로 수정 시도 시 400

**2026-10-09 가정 A2/Q22 해결** — 「가격만 보내는 부분수정」이 된다.
상품 전체를 우리가 SSOT 로 들고 있을 필요가 없다.

> ★ 그러나 `""` 와 `null` 의 차이가 곧 **지움과 안 건드림**이다 ★
>   빈 문자열을 「값 없음」으로 보내는 흔한 손버릇이 여기서는 **컬럼을 지운다.**
>   보내지 않을 필드는 **키 자체를 빼거나 `null`** 로 둔다.
>   (`dont-overwrite-what-you-couldnt-read` 와 같은 자리다 — 모르는 것과 비어 있는 것은 다르다)

### `GET /v3/sb/product-info-notice/:noticeType`

## 8-B. ★ 재고를 쇼핑몰로 «미는» API 는 OMS 에 없다

문서 전체에서 재고 관련은 둘뿐이다.

| 있는 것 | 뜻 |

| `shopMallStockRate` (channels-product) | 몰별 재고 **비율(%)** — 수량이 아니다 |
