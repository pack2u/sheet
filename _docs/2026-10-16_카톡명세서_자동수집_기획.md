> "지금 쌓이는것은 카톡에서 이미지로 온 업체들 비미지 붙여 넣기로 수종 작업한거야..

> "명세서는 시트에도 적으면 좋은데 문제가 있을까?"

## 1. 먼저 못 박을 사실 — 카톡은 이미지를 자동으로 안 내준다

★ 이 한 줄이 기획 전체를 가른다. 그래서 먼저 확인했다. ★

- **카톡 PC 는 받은 이미지를 자동 저장하지 않는다.** 사람이 저장을 눌러야 한다.
  ([카카오 데브톡 답변](https://devtalk.kakao.com/t/pc/43138) — 오래된 글이라
  현재 판은 PC 에서 한 번 확인해야 한다)
- 받은 파일 폴더 설정은 있다(`환경설정 › 채팅 › 다운로드 폴더`, 기본은
  `문서\카카오톡 받은 파일`). 하지만 그건 **저장을 누른 뒤** 어디로 갈지일 뿐이다.
  ([참고](https://extrememanual.net/40021))
- 개인·단톡 대화를 읽는 **공식 API 는 없다**. 카카오 비즈니스 채널 쪽만 열려 있다.

그러므로 「폴더만 보면 저절로 쌓인다」는 **그대로는 안 된다.**
입구를 어떻게 만드느냐가 이 기획의 전부다.

## 2. 뼈대 — 입구는 여럿, 판독은 한 곳

```
 [입구]                        [한 곳]              [두 갈래]
 ① 카톡 저장 폴더 감시 ┐
 ② 메일 첨부          ├─→  v2 명세 수신함  →  판독(OCR)  ─┬─→ 검산: 대리공급과 맞대기
 ③ 폰 갤러리 → NAS    │      (statement-src)              │     → ★다른 것만★ 사람에게
 ④ 화면에서 끌어놓기  ┘                                   └─→ 보기: 시트 한 탭에 거울
```

★ 입구를 여럿 두되 **판독은 반드시 한 벌** ★
이미 「정산 파이프라인 — 입구는 둘, 판독은 v2 한 곳」으로 가고 있는 것과 같은 모양이다.
입구마다 판독을 따로 두면 언젠가 한쪽만 고쳐진다.

### 업체는 «이미지에서» 알아낸다 — 대화방 이름에 기대지 않는다

어느 입구로 들어와도 대화방 이름은 따라오지 않는다. 그러니 **명세서 자체**를 읽는다.

10/14 에 `거래명세표_거래처` 탭에 11곳의 **등록번호·상호·주소·대표자**를
채워 두었다. 이것이 그대로 열쇠가 된다 —

| 읽는 것 | 왜 |
|---|---|
| **사업자등록번호** | 가장 튼튼하다. 오타가 없고 한 곳에 하나다 |
| 상호 | 등록번호를 못 읽었을 때 |
| 발행일자·합계금액 | 같은 업체의 여러 장을 가른다 |

## 3. 입구 네 가지 — 무엇을 먼저 할까

### ① 카톡 저장 폴더 감시

사람 손을 **「캡처 → v2 열기 → 붙여넣기」에서 「우클릭 → 저장」 한 번으로** 줄인다.

```
카톡에서 우클릭 → 저장  →  D:\명세서받은함\  →  수집기  →  v2
```

- 수집기는 **바이토 수집기와 같은 꼴**이다(NAS `바이토수집기`). 새로 배울 것이 없다
- 30분마다 새 파일만 올린다. 올린 파일은 `올림\` 으로 옮겨 두 번 안 보낸다
- 못 올린 파일은 그 자리에 남긴다 — ★ 지우지 않는다 ★

**좋은 점** 개인 사진이 안 섞인다. 어느 대화방인지 사람이 안다
**걸림돌** 저장을 누르는 손이 남는다

### ② 메일 첨부 — 같은 수신함으로  ★ 이게 제일 먼저 끝난다 ★

v2 가 Gmail 을 읽어 PDF·JPG 첨부를 같은 수신함에 넣는다.
제목 거르개는 10/14 에 이미 맞춰 두었다 —

```
in:inbox -from:me has:attachment (subject:명세서 OR subject:명세표 OR 마감)
```

14일치 20건이 전부 진짜 명세서였다(잡것 0). **거를 일은 끝나 있고, 읽을 일만 남았다.**
로엔그린·후아코리아·준테크가 매일 메일로 보낸다. **손이 아예 안 간다.**

### ③ 폰 갤러리 → NAS

폰 카톡의 「사진 자동 저장」을 켜고, 시놀로지 Photos 백업으로 NAS 에 올린다.

**좋은 점** 누르는 손이 없다
**걸림돌** ★ 개인 사진까지 전부 NAS 로 간다 ★. 전용 폰이 아니면 권하지 않는다

### ④ 화면에서 끌어놓기

`/statements` 에 사진을 끌어다 놓으면 바로 판독. 지금 하시는 일의 **빠른 판**이다.
어느 입구도 안 닿는 건(현장에서 받은 종이, 문자로 온 것)을 위한 비상구.

## 4. 판독 — 무엇을 읽고, 무엇을 안 믿나

읽는 것: 등록번호 · 상호 · 발행일자 · 합계금액 · 품목 줄

★ 못 읽은 칸은 비워 둔다 ★ 모르는 것과 비어 있는 것은 다르다.
짐작해 채우면 대사가 조용히 틀어진다.

### 판독이 틀린 것을 값싸게 잡는 법 — 두 번 읽기

같은 이미지를 **두 번 읽어** 숫자가 다르면 사람에게 넘긴다.
OCR 은 흐린 글자에서 흔들리는데 **두 번 다 같게 틀리는 일은 드물다.**
한 장에 몇 초다. 이것이 「판독 자체가 틀렸나」를 잡는 유일하게 싼 길이다.

### 판정 세 갈래

| | 뜻 | 다음 |
|---|---|---|
| **붙음** | 등록번호가 맞고 날짜·금액이 하나로 떨어진다 | 바로 `statements` 에 |
| **물음** | 업체는 알겠는데 금액이 안 맞거나 같은 날 두 장 | 사람이 고른다 |
| **모름** | 명세서가 아니거나 못 읽었다 | 수신함에 그대로. ★ 안 버린다 ★ |

명세서가 아닌 이미지(사진·짤)가 섞이는 것은 **막을 수 없다.**
막으려 들면 진짜 명세서를 놓친다 — **「모름」으로 두고 사람이 치우게** 한다.

## 5. ★ 검산과 보기는 다른 일이다 ★

> "시트와 비교가 되어서 오히려 오류를 잡을수 있지는 않을까?"

**사본은 증인이 아니다.** v2 가 시트에 적은 값은 v2 값의 사본이라, 맞대 봐야
언제나 같다 — 판독이 틀렸으면 **똑같이 틀린 값이 두 곳에** 앉는다.
그래서 「시트에 적어 두고 눈으로 견준다」로는 오류가 안 잡힌다.

오류를 잡으려면 **다른 데서 온 값**이어야 한다. 그런 증인이 셋이다.

| 증인 | 무엇을 잡나 | 지금 |
|---|---|---|
| **우리 대리공급 기록** | 업체가 청구한 것 ↔ 우리가 받은 것 (금액·수량) | ★ 진짜 비교 상대 ★ 정산 대조가 이미 v2 에 있다 |
| **이카운트 구매 전표** | 장부까지 맞는지 | 하루 끝 엑셀로 들어온다 |
| **원본 이미지** | 판독 자체가 틀렸는지 | 사람 눈. 그래서 원본을 안 지운다 |

### 그래서 둘로 나눠 이름을 똑바로 붙인다

**㉠ 검산 — v2 에서 자동으로**
명세서 ↔ 대리공급을 맞대고 ★다른 것만★ 올린다. 세트분리·대리공급에서
「다름 0」을 세고 있는 그 방식 그대로다. 하나팩 10월 중복 79.7만원도 그렇게 걸렸다.

**㉡ 보기 — 시트 한 탭에 거울**
검산용이 아니다. 「이번 달 몇 장 왔나」, 「이 업체 것이 왜 없지」를 **익숙한
자리에서 훑기 위한 것**이다.

| | |
|---|---|
| **주인** | v2 하나. 고치는 것도 v2 에서만 |
| **어디에** | **한 파일 · 한 탭** (예: 허브의 `명세서_수집`). 전 업체가 한 탭에 모인다 |
| **공유** | 그 **한 파일만** 서비스 계정에 편집자. ★ 업체 파일은 안 건드린다 ★ |
| **탭 맨 위에** | 「여기 적힌 것은 v2 의 사본입니다. 고쳐도 다음에 덮어씁니다. 검산은 /statements 에서 합니다」 |

★ 업체 파일에 직접 적지 않는 까닭 ★ 옛 GAS 는 업체 파일의 `명세서_원본` 탭에
적었다. 그대로 하면 ①업체 파일 수십 개를 서비스 계정에 편집자로 공유해야 하고
(지금은 문서 하나·탭 하나만 열려 있다 — `google-sheets.ts` 쓸수있는문서/쓸수있는탭),
②업체 파일의 자동 열(스필)을 건드릴 위험이 있으며, ③한 업체만 공유가 안 되면
그 업체 것만 **조용히** 안 들어간다. 한 탭에 모으면 셋 다 피한다.

## 6. 사람이 보는 화면 — `/statements`

- 수신함: 안 읽은 것 · 물음 · 모름. 썸네일과 읽어 낸 값을 **나란히**
- 한 줄 고치기: 업체·날짜·금액만. 고치면 그 업체 이름을 배운다(정산 대조와 같은 방식)
- 되돌리기: 잘못 붙인 건 떼어 수신함으로
- **원본 이미지는 지우지 않는다.** 숫자를 의심할 때 볼 것이 그것뿐이다

## 7. 순서 — 작게, 확인하면서

| | 할 일 | 끝났다는 뜻 |
|---|---|---|
| **1** | v2 명세 수신함 + 판독(두 번 읽기) + `/statements` 수신함 화면 | 손으로 올린 이미지가 자동으로 읽힌다 |
| **2** | **메일 입구** (②) | 로엔그린·후아·준테크가 매일 저절로 들어온다 |
| **3** | **검산** — 명세서 ↔ 대리공급 맞대기, 다른 것만 올림 | 틀린 청구가 사람 눈 앞에 온다 |
| **4** | **시트 거울** — 한 파일·한 탭 (보기용) | 익숙한 자리에서 훑을 수 있다 |
| **5** | **카톡 폴더 감시** (①) | 「저장」 한 번이면 끝 |
| **6** | 그림자 1주 — 손 작업과 **맞대기** | 7일 「다름 0」이면 손 작업을 끈다 |
| **7** | (고르면) 폰 → NAS (③) | 누르는 손도 없앤다 |

★ 6번을 건너뛰지 않는다 ★ 「그림자 일주일」로 세트분리·입금·판매현황을 다
그렇게 넘겼다. 숫자가 맞는 것을 **본 뒤에** 손을 뗀다.

## 8. 정하실 것

1. **카톡 받는 자리** — 어느 PC·어느 계정으로 업체들이 보내나? 그 PC 가 수집기를 돈다
2. **③(폰→NAS) 를 쓸까** — 전용 폰이 있나? 개인 사진이 섞여도 되나?
3. **업체에 메일을 부탁할까** — 카톡으로 보내는 업체에 「명세서는 메일로」를 부탁하면
   ②만으로 거의 다 덮인다. 가장 튼튼하지만 업체를 움직여야 한다
4. **거울 탭을 어느 파일에** — 허브? 상품정보시트? 그 한 파일만 편집자 공유가 필요하다

### 정해진 것 (10/16)

- 명세서는 **v2 가 주인**. 시트에는 **보기용 거울**만, **한 파일·한 탭**에.
  고쳐도 다음에 덮어쓴다고 탭에 박아 둔다
- 검산은 **시트 사본과의 비교가 아니라** 대리공급 기록과의 자동 대조로 한다
- GAS 의 Gmail 명세 수집은 **메뉴에서 뺐다**(코드는 남김)

## 덧 — 확인이 필요한 것 하나

카톡 PC 의 자동 저장 여부는 **오래된 글**로 확인한 것이다.
요즘 판에 「사진 자동 다운로드」 같은 설정이 생겼다면 ①의 손이 아예 없어진다.
사장님 PC 에서 `환경설정 › 채팅` 을 한 번만 봐 주시면 거기서 갈린다.
