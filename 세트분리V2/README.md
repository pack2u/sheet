# 세트분리 V2

구 시트 **「세트분리(사용중)」** 를 대체하는 엔진. 같은 입력에서 같은 결과를 내되,
[진단서](https://claude.ai/code/artifact/6e39588b-5f39-4ee4-96d5-4cdd193ca7ae)에서 잡은 결함을 구조적으로 제거했다.
로젠택배 → **롯데택배** 로 이름만 바뀌었고 출력 열 구성(19열)은 그대로다.

두 가지 방식으로 같은 코드를 돌린다.

| | 어디서 | 언제 쓰나 | 속도 |
|---|---|---|---|
| **시트** | 「세트분리(뉴)」 스프레드시트 메뉴 | 매일 운영 | 수 초 |
| **로컬 CLI** | `node node/run.mjs` | 검증 · 대량 재처리 · 무인 자동화 | **0.2초** |

계산 로직은 `core.js` **한 파일**에 있고 Apps Script와 Node가 그 파일을 그대로 공유한다.
시트와 CLI의 결과가 갈라질 수 없다.

3. `합배송조건` · `분리예외` 탭에 구 시트 내용을 복사해 넣는다 (구 시트의 같은 이름 탭).
   구 시트에서 복사하면 C열에 `#REF!` 수식이 따라온다 — **🧹 합배송조건 정리 / 검증** 을 실행하면
   값으로 덮어쓰면서 품목정보에 없는 코드·중복 조건을 D열 비고에 표시한다.
   (「① 마스터 새로고침」 때도 자동으로 같이 돈다)
4. **🏝 도서산간 목록 심기 (1회)** → 시/군 21개 · 우편번호 734개 · 이미 확인된 주소 14건 적재.
5. **① 마스터 새로고침** → 이카운트에서 품목·재고·BOM을 당겨온다.

### 재고는 실행할 때마다 다시 읽는다

재고는 하루에도 여러 번 바뀐다 (이카운트 OAPI → `ecount.gs` → 상품정보 시트 `이카운트-재고`,
07시·11시·12시·01시 트리거 + 수동). 구 시트는 IMPORTRANGE 라 원천이 바뀌면 자동으로 따라왔다.

V2 는 `설정` 탭의 **`실행전_마스터갱신`** 으로 같은 신선도를 유지한다.

| 값 | 동작 | 언제 |
|---|---|---|
| `재고만` (기본) | 실행 직전 `M_재고` 만 다시 읽음 | 평소 |
| `재고+품목` | 재고 + 품목정보(상태·출고지·배송비) | 낮에 품절 처리가 잦을 때 |
| `전체` | 마스터 새로고침 전부 | 마스터를 크게 손댄 직후 |
| `안함` | 갱신 없이 현재 스냅샷으로 계산 | 재현·검증용 |

`실행요약` 에 **재고 기준시각** 과 **품목정보 기준시각** 이 찍히고,
재고가 6시간보다 오래됐으면 `STOCK_STALE` 경고가 뜬다.
갱신에 실패하면 직전 값으로 계속 계산하되 `PRERUN_REFRESH` 오류를 남긴다.

### 동네배송은 현재 중단

`설정` 탭의 **`동네배송_사용`** 이 기본값 `중단` 이다. 이 상태에서는

- 마스터 새로고침이 동네배송 원천을 아예 건드리지 않는다 (경고도 안 낸다)
- 라우팅이 `롯데택배-동네배송` 을 절대 고르지 않는다
- `동네배송_금일` · `롯데택배-동네배송` 두 탭은 **숨김** 처리된다 (지우지 않는다)

나중에 다시 쓰려면 `동네배송_사용` 을 **`사용`** 으로 바꾸고 마스터 새로고침만 하면 된다.
탭이 다시 보이고 분류가 되살아난다. 코드는 손댈 필요 없다.
원천 시트가 바뀌었으면 `동네배송시트ID` · `동네배송_탭` 도 함께 고친다.

도서산간 목록은 거의 바뀌지 않는 준정적 데이터라 `gasSeed.js` 에 그대로 넣어 두었다.
원천 시트를 다시 쓰게 되면 「① 마스터 새로고침」이 알아서 최신값으로 덮어쓴다.
붙여넣기용 CSV도 `seed/` 에 있다 (`도서산간_시군` · `도서산간_우편번호` · `도서산간_주소사전`).

### 매 회차

1. **② 판매현황 비우기** → 이카운트 판매현황 엑셀을 `판매현황` 탭 2행부터 붙여넣기.
2. **▶ 세트분리 실행**.
3. `실행요약`에서 *분해 = 출력 + 흡수* 가 **OK** 인지 확인, `보류`·`경고` 탭 확인.
4. 출력 탭에서 롯데 양식으로 복사.

### 탭 구성 — 분해된 모든 행이 정확히 한 탭에 들어간다

| 탭 | 내용 |
|---|---|
| `롯데택배` · `롯데택배-동네배송` | 각 1행 = 송장 1건 |
| `롯데택배-도서산간` · `롯데택배-도서산간(위탁배송)` | 앞에 `권역`(제주/도서) · `우편번호` · `판정`(지역확정/우편번호) 3열이 더 붙는다 |
| `대리발송` | 재고 부족분, 협력업체로 넘기는 건 |
| `합배송` | 한 박스로 묶인 건. `구분` 열이 **대표**(송장 나감) / **동봉**(같은 박스에 들어감), `실제경로` 열에 원래 경로 |
| `보류(미발송)` | **분류되지 않은 모든 행** + 보류사유 |

`분해행 = 모든 탭 행수 합계` 가 항상 성립한다. 어긋나면 `ROW_LOSS` 오류가 뜬다.
실제 송장 건수 = 탭 합계 − 합배송 동봉 − 보류.
**🔍 검증** 메뉴가 이 등식과 탭 간 중복을 한 번에 확인해 준다.

### 도서산간 — 우편번호로만 판정한다

판정 기준은 **우편번호 하나**다. 도시 이름은 판정에 쓰지 않는다.

```
주소 → (사전에 우편번호 있나?)
        ├─ 있다 → 734개 목록에 있으면 도서산간(권역), 없으면 일반 롯데   ← 끝
        └─ 없다 → 지역명 확인
                  ├─ 제주·서귀포·울릉  → 우편번호 없이 도서산간 확정
                  ├─ 그 외 후보        → 설정에 따라 보류 또는 일반출고 + 경고
                  └─ 아무것도 안 걸림  → 일반 롯데
```

처음엔 지역명으로 후보를 거르고 후보만 우편번호를 확인했는데, 그 방식은 못 쓴다.
`여수`·`목포`·`군산`·`안산`·`통영`·`완도` 는 **대부분 육지 도시**라
도시 전체가 후보가 되고 우편번호를 못 구한 건이 죄다 보류로 쏟아진다.

지금은 롯데로 나가는 **모든 주소**의 우편번호를 `도서산간_주소사전` 에 한 번씩만 쌓는다.
사전은 영구 캐시라 같은 주소를 두 번 조회하지 않고, 쌓일수록 보류가 줄어든다.
한 회차 조회 상한은 `설정` 의 `우편번호_최대조회` (기본 300).
카카오가 못 찾은 주소는 `메모` 에 실패로 남고 매 회차 재시도하지 않는다 — 직접 넣으면 된다.

`권역` 은 롯데 청구 항목에 맞췄다.

| 권역 | 우편번호 | 롯데 청구 |
|---|---|---|
| `제주` | 63xxx (목록 734개 중 511개) | `제주연계` — 2026-07 청구 기준 3,000원 정액 |
| `도서` | 그 외 223개 | `도선료` · `산간료` — 지역·무게별 변동 |

권역 값은 `도서산간_우편번호` · `도서산간_시군` 탭에서 직접 고칠 수 있고,
마스터 새로고침이 덮어쓰지 않는다. 금액은 계산하지 않는다 — 롯데 청구서로 사후 정산.

지역명 목록은 이제 **우편번호를 못 구했을 때의 안전망**일 뿐이다.
`확정=Y` (제주·서귀포·울릉)만 단독으로 판정 근거가 된다.
한 글자 키워드는 무시하고 `ISLAND_KW` 경고를 낸다.

### 우편번호는 카카오가 채운다

`▶ 세트분리 실행` 이 우편번호가 필요한 도서산간 후보를 만나면 스스로 처리한다.

1. 후보 주소를 `도서산간_주소사전` 에 추가
2. **카카오 로컬 API**로 우편번호 조회 (`gasZip.js`)
3. 채워졌으면 파이프라인을 **한 번 더 돌려** 결과에 반영

사람이 우편번호를 찾아 넣고 재실행하던 단계가 사라진다.
API 키는 코드에 없다 — **🔑 카카오 API 키 설정** 메뉴로 한 번 넣으면 Script Properties 에 저장된다
(상품정보 프로젝트 `_partnerExclusivePush.gs` 에서 쓰던 키를 그대로 넣어도 된다).
카카오가 못 찾은 주소는 `ZIP_FAIL` 경고로 뜨고 사전에 직접 입력하면 된다.
**사람이 넣은 값은 절대 덮어쓰지 않는다.**

## 2. 로컬 CLI (시트 없이)

```bash
node node/run.mjs --masters <마스터.xlsx> [--sales <판매현황.xlsx>] [--out out]
```

`--masters` 는 구 시트 내보내기(legacy)와 신 시트 내보내기(v2) 둘 다 자동 인식한다.
`--sales` 를 생략하면 마스터 파일 안의 `판매현황` 탭을 쓴다.
결과는 UTF-8 BOM CSV라 엑셀에서 바로 열린다.

```bash
node node/test.mjs                      # 단위 테스트
node node/verify.mjs <구시트.xlsx>       # 구 시트 출력과 한 줄씩 대조
```

의존성 없음 (xlsx 리더까지 직접 구현). `npm install` 불필요.

## 3. 구 시트 대비 무엇이 달라졌나

| 구 시트 문제 | V2 처리 |
|---|---|
| 탭마다 다른 고정 행 상한 (2,564 / 3,011 / 3,410 / 3,026 / 2,715 …) | 배열 수식이 없다. 상한 개념 자체가 없음 |
| 출력 4탭 필터가 겹침 → 중복 출고 | 라인마다 `route` **한 값**. 출력 탭은 그 값으로 나누기만 함 |
| `합배송!X2` 가 조건ID를 품목코드로 재조회 | 조건ID를 라인에 저장. 다시 찾지 않음 |
| 배송비를 품목명 문자열에서 정규식으로 파싱 | `M_배송비규칙` 정규 테이블. 파싱은 마스터 새로고침 때 **1회**, 실패는 경고 |
| BOM 소요량 무시 | `수량 = 주문수량 × 소요량` |
| IMPORTRANGE 실패가 "해당 없음"과 구분 안 됨 | 실패하면 **예외를 던지고 멈춘다**. 이전 마스터가 그대로 남음 |
| 도서산간 우편번호 미입력 → 조용히 일반 출고 | **보류 + 사유**. 후보 주소를 사전 탭에 자동 추가 |
| 행 단위 수식 8,889개로 O(n²) | 전 구간 O(n) 해시 조인 |
| 판매현황이 하루 2번 지워지며 이력 소실 | `주문라인원장`·`실행이력` 누적 |
| 어디로도 안 간 행이 조용히 사라짐 | 전부 `보류(미발송)` 탭 + 사유. 분해행 = 탭 합계 검증 자동 |
| 합배송 대표행이 일반 출고에 섞여 구성이 안 보임 | `합배송` 탭에 대표+동봉을 박스 단위로 묶어 표시 |
| 도서산간 우편번호를 매번 사람이 검색 | 제주·울릉은 주소만으로 확정, 나머지는 카카오 API 자동 조회 + 사전 누적 |
| 도서산간이 로젠 기준 한 덩어리 | 롯데 청구 항목(제주연계 / 도선료·산간료)에 맞춘 `권역` 열 |

### 구 시트 규칙 중 **일부러 그대로 둔 것**

- **상태·출고지는 원본 세트 코드 기준**, 품목명·배송비는 구성품 코드 기준.
  (구 시트 `변환!B:C` 가 판매현황 품목코드로 조회하는 것과 동일. 세트가 판매중이면 구성품도 함께 나간다)
- 상태 판정은 **부분일치**. `품절임박` → `임박` 으로 통과, `판매중(재고까지만)` → `판매중` 으로 통과.
- 합포장 품목명 압축(`BF 225파이 감자탕 대/중/소 블랙`)은 구 시트 커스텀 함수
  `groupItemNamesWithCondition` 의 실제 출력에서 역설계해 재구현했다 (`ssCompressNames`).
  규칙: 공통 앞 토큰 2개 이상 + 가운데 남는 토큰 수가 같을 때만 `/` 로 접는다.

## 4. 검증 결과 (2026-09-02 오전 회차 스냅샷)

```
입력 판매현황 210행 → 세트분해 247행 → 합포장 흡수 36 → 출력 211
구 시트 출력과 대조 : 일치 208 · 신에만 2 · 구에만 2  (같은 2줄이 다른 탭으로 갔다)
```

**차이 2건** = 순번 118, 제주특별자치도 제주시 주문 2줄.
구 시트 `도서산간분류확인` 탭에서 우편번호가 비어 있어 "도서산간 아님"으로 처리되어
일반 롯데(로젠) 출고로 나갔다. V2는 주소만 보고 `롯데택배-도서산간 / 권역 제주` 로 분류한다.
**실제로 제주 추가배송비가 미청구된 건**이다.

그 밖에 마스터 새로고침이 잡아내는 데이터 오류 — 배송비 규칙 문자열 **33건 해석 불가**:

```
AJONETOUCH00006   4개(완박스)5500      ← 하이픈 누락
APSFH10001~10003  4개(완박스)          ← 금액 자체가 없음
BFONETOUCH00006   4개(합포장)4500      ← 키워드 다름 + 하이픈 누락
IMCGTR1004/1005   200/200/200/200/200  ← 수량 표기 없음
SWPAC30001/30004  2750                 ← 수량 표기 없음
```

전부 구 시트에서는 `IFERROR` 에 삼켜져 **단품배송비 × 수량**으로 조용히 청구되던 것들이다.

## 5. 파일

```
core.js         순수 파이프라인 (GAS + Node 공용). 여기만 고치면 양쪽 다 바뀐다
gasIO.js        시트 읽기/쓰기 · 설정 탭
gasMasters.js   외부 스프레드시트 → 로컬 마스터 탭
gasMain.js      메뉴 · 설치 · 실행 · 검증
gasSeed.js      도서산간 목록 초기 적재 (1회용)
gasZip.js       카카오 로컬 API 우편번호 조회
node/xlsxread.mjs  의존성 없는 xlsx 리더
node/masters.mjs   xlsx → 마스터 (legacy/v2 자동 인식)
node/run.mjs       CLI
node/verify.mjs    구 시트 대조
node/test.mjs      단위 테스트
```

배포: `clasp push` (이 디렉터리에서). `node/` 는 `.claspignore` 로 제외된다.
